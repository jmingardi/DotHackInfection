# Graphical launcher QA - 2026-11-16

Entry point: `DotHackInfection.exe`, launcher 0.1.0, Windows x64/.NET Framework 4.8.
Sources are under launcher/. It uses a small native bridge compiled from the
pinned framework's existing host/keymap.cpp; no runtime source patch was added.
Framework and SDL2 notices are copied into launcher-bin/licenses/.

Verified:

- GUI opens directly without Python or CMD. It verifies the supported USA ISO
  using the recorded SHA-256, reads the image in place, and disables Play for
  unsupported/missing input. The verification worker keeps the GUI responsive.
- Twenty-six core checks pass: shared native parser/defaults, keyboard/mouse
  capture, reserved-key rejection, duplicate-binding swaps, alternatives, display
  settings, comment/timing preservation, reset, atomic backups, memory-card
  preservation, restart persistence, external-edit refusal, compatibility flags,
  Windows argument quoting and ISO rejection/read-only behavior.
- Actual GUI keyboard capture changed Cross to G. Display selection set 2x.
  Save settings persisted both and preserved a custom INI comment.
- Play invoked the native ps2run.exe with an isolated private save directory,
  supported ISO, shared completed-code cache, and the existing stick-center,
  selected VU reference and delayed-XGKICK compatibility profile.
- Native log confirms resolution 2x, completion at 600 frames and exit 0.
  The launcher returned to its window and closed cleanly after play.
- Personal saves/keys.ini SHA-256 stayed unchanged. The game executable stayed
  byte-identical to the prior QA build:
  `3389e49165fc75984cf917821f5834e8a56378d6634dcb37ca28940e2dd9ea43`.
- Existing ps2padtest and ps2savetest completed successfully.
- Main, controls and display screenshots were inspected; a clipped verification
  label and binding-grid scroll reset were corrected before the successful run.

Successful real-window evidence:
`evidence/qa-launcher-gui-20261116T173051565/`, including home.png, controls.png,
display.png, report.json and profile/launcher-logs/. Test profiles and raw logs
remain local and ignored. Earlier stopped UI-automation attempts are preserved.

Reproduce after a normal framework bootstrap/build:

```powershell
python scripts/project.py build-launcher
```

Core checks use a new evidence directory on each run:

```powershell
.\DotHackInfection.exe --profile-dir "$PWD\evidence\qa-launcher-self-new" --self-test
```

Inspect self-test.json and the process exit code (PowerShell may return from a
GUI EXE immediately; use Start-Process -Wait -PassThru for scripted runs).
Real GUI/native boot:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File qa/launcher_ui.ps1
```

QA startup/frame-limit switches require a profile inside this project's evidence/
folder. Normal users need only double-click the launcher; no QA switches.

Controller input currently uses the runtime's automatic SDL2 device assignment;
the GUI edits keyboard/mouse bindings and detects controllers, without claiming
per-device controller rebinding. No physical controller was newly qualified.
Windowed native boot/2x resolution were exercised; borderless arguments were
checked but a new fullscreen gameplay session was not performed. Resizing/DPI
support follows WinForms and has been visually checked on this PC only.
The original 4:3 presentation, game timing and pacing lines are preserved.
Widescreen, altered frame rates and complete campaign QA remain deferred.

The launcher uses the existing local runtime, compiler and cache for on-demand
translation. It is not a standalone portable release package. Nothing was
published, uploaded or installed globally as part of this launcher work.
